# SOP：制作一个小节

从零做出一个小节（知识点卡片 + 20 道题），到复核通过、提交入库的完整流程。第 1 章 5 个小节按这个流程做完，每节平均 3 轮复核。

## 0. 准备

确认三件事，缺了就先问项目维护者，不要凭记忆写：

- 本节教什么：查 `docs/textbooks/math-sh2024-g6s1.md` 的知识范围
- 之前学过什么：前面所有小节的知识都能用
- **还没学什么**：这是超纲的判断依据。第 1 章尤其注意——字母表示数、方程、幂的运算法则都在后面

然后**查题型台账** `docs/question-types.md`：

- 看"套路总表"的定位列：**核心**题型看前面用过几次、什么情境，本节有计划地复现（换情境、换坑或多叠一步）；**一次性**的巧题确认没出过
- 从"还没用过的套路池"里挑新套路（带 ※ 的更容易做足挑战档要求）
- 如果 `docs/references/` 下有教辅笔记，一并翻一下，学题型和难度标尺（用法和红线见台账第四节）

## 1. 设计三档（动笔前先列提纲）

先列 20 道题各考什么，再写具体题目。这一步没做好，后面会被整节打回。

新做或重做的小节用**真卷标尺**（样板：6 上 1.2）：

| 档位 | 题量 | 标准（详见 AGENTS.md） |
|---|---|---|
| 基础 | 9 | 真卷常规题（1～2 级），1～3 步，**每道都有一个“坑”** |
| 扩展 | 6 | 真卷中档难题到压轴（3～5 级，大约 3∶2∶1），要有转弯 |
| 挑战 | 5 | 比真卷压轴再难一些，关键转化后再推广或分类，5～7 步，不偏竞赛 |

旧的上移标准（基础 5 + 扩展 10 + 挑战 5，挑战到竞赛复赛中档）已不再使用，见 AGENTS.md。

设计挑战题时，先写下这一句再动笔：

> 这道题叠加的两个环节是：____ 和 ____。

**反面清单**（命中任意一条就换题）：

- 和本节某道扩展题是同一个模板，只换了数据
- 只有一个环节：一次分类、一次裂项、一次找规律、一次符号判断
- 能硬算：项数太少（比如只有 9 项、24 种情况）
- 能取特殊值秒杀，或者选项只有两个、做完前两问就能排除
- 数集正负对称，导致"最大值"和"最小值"互为相反数，白送一问

## 2. 写内容

- 文件：`content/<学科>/<教材>/<册>/<小节号>.js`，格式见 AGENTS.md
- 卡片 3～6 张；新小节按 `b01…b09 / e01…e06 / c01…c05` 编号；重做旧小节时，新题接着已有的最大序号编，删掉的题号不复用
- **能算的题必须写 `verify`**：用 `F()` 精确分数运算，或者穷举、模拟。不要返回写死的答案——`verify` 抓到过我写错的数学结论
- 解析只用已学方法；分步写；挑战题要讲清思路怎么想到的

## 3. 自查（送审前必做，逐条对照）

这一步能拦掉复核最常打回的问题：

- [ ] `node tests/run.js` 通过，0 失败 0 提醒
- [ ] **卡片例子逐条对照 20 道题**，包括例子的中间步骤，不能泄露任何一题的答案或第一步
- [ ] 题目之间不撞模板：把 20 道题的"考点 + 方法"列出来。扩展档、挑战档里同一套路只出一次；基础档两道同一核心题型时，坑要不同
- [ ] 解析里没有出现：设字母、列方程、幂的运算法则，以及其他还没学的方法
- [ ] 多值填空写明"全部填出，用逗号隔开"；只有一个值时写"有几个就填几个"
- [ ] 分数答案能接受带分数、小数等写法（判分器已支持，确认答案本身格式正确）
- [ ] 题干措辞无歧义：动点是否折返、是否停留、"第几秒"还是"运动多少秒"、有序还是无序

## 4. 盲解复核（交给另一个干净的 AI 会话）

```bash
node tests/export-blind.js <小节ID> <scratchpad>/blind-<小节号>.md          # 全节
node tests/export-blind.js <小节ID> <scratchpad>/blind-<小节号>.md c01 c02  # 只导出指定题
```

导出的题单**不含答案、解析和 verify**。复核方必须是没见过答案的干净会话：Claude Code 用子代理，其他工具另开一个新会话。每个小节开一个新的复核会话；同一小节的后续轮次发回给原来的会话（它记得上下文）。

提示词模板见本文末尾附录，按小节替换占位符即可。

## 5. 处理复核意见

| 复核说法 | 处理方式 |
|---|---|
| 答案和我的不一致 | **先查清楚谁对**，不要默认自己对。这是最高优先级 |
| 超纲 | 必须改：换方法、改解析，或整题替换 |
| 歧义、答案不唯一 | 必须改题干 |
| 卡片撞车 | 必须改，改卡片例子或改题 |
| 挑战题"未达到" | 必须改或换题，直到通过 |
| 换数版（题型、情境、步骤都一样，只换数据） | 必须改其中一道 |
| 和前面小节同一核心题型 | 是有计划的复现就保留：确认换了情境或多了一步，在台账里记上；只是换数版就改 |
| 难度"偏下限""勉强达到" | 可以保留，记录在案 |
| 与本节知识点关联弱 | 补进解析里说明联系，或换题 |

改完后**再送一轮**，只导出改过的题。重复 4～5，直到复核明确写出"整节通过"。第 1 章每节都用了 3 轮。

## 6. 收尾

- **更新题型台账** `docs/question-types.md`：把本节新用的套路补进"套路总表"（标注定位：核心 / 一次性，来源：自创 / 参考某教辅）和"按小节明细"；核心题型的复现记在原来那一行的“用在”里
- 在小节文件写入 `audit: { blind, rounds, note }`
- `catalog.js` 标记 `ready: true`
- `node tests/run.js` 全绿（提醒也要清零）
- 手机宽度截图抽查 2～3 道新题（多空、长选项、特殊符号的题）
- 提交 git，说明这一节做了什么、复核几轮

## 完成标准

一个小节算做完，要同时满足：

1. 测试 0 失败 0 提醒
2. 复核方明确写"整节通过"
3. 所有能算的题都有 `verify` 且与答案一致
4. `audit` 记录已写入
5. 界面上能正常显示（截图确认）
6. 题型台账已更新

不满足第 2 条就不算完成，哪怕已经改了三轮。
